# Affordable Life — shared housing & office rental platform

Premium places, shared costs. A South African platform where students, young professionals,
visitors and businesses register interest in verified shared homes or offices, then complete a
guided application with document uploads. Staff review everything in a built-in admin panel.

**Stack:** Next.js 16 (React 19) frontend + Payload CMS 4 backend (Node.js) in one app,
PostgreSQL database, Tailwind CSS v4.

| Part | Where |
| --- | --- |
| Public website (React) | `src/app/(frontend)` and `src/components` |
| Backend: data models, access rules, hooks | `src/collections`, `src/payload.config.ts` |
| Server actions (forms, applications, uploads) | `src/app/(frontend)/*/actions.ts` |
| REST & GraphQL API, admin panel | `/api/*`, `/admin` (generated by Payload) |
| Database migrations | `src/migrations` (applied automatically on start) |
| First-run admin + demo data | `src/seed` |

## Features

- Home page, browse/search/sort homes, list and map views, saved homes and saved searches
- Home detail pages with plain monthly pricing, group progress and "just me / with friends" joining
- Suburb pages (`/cape-town/rondebosch`, …) with a live public demand counter
- Audience pages: Personal, Students, Professionals, Visitors, Businesses, Corporate
- Pricing with an occupancy stress-test calculator, suburb finder quiz, Trust, Help, About, Privacy
- **Register interest** (stage 1) → **9-step application** (stage 2): details, profile, space,
  payment, payer/sponsor, references, document uploads (PDF/JPG/PNG/HEIC, 10 MB), consent, review
- Drafts resume securely via a private browser token, or from a member account
- Member accounts: register, log in, profile, "My applications", continue drafts
- Property partners can submit a property for verification
- Admin panel (`/admin`) for homes, suburbs, demand, applications, documents, partner submissions
- **Tenant dashboard** (`/account`): next payment, tenancy, invoices with online payment and receipts,
  maintenance requests with live status, applications and profile
- **Partner portal** (`/partner`): occupancy, rent collected, maintenance (update status and leave notes
  for tenants) and payout statements for each landlord's homes
- **Operations dashboard** (`/ops`, staff only): collections chart, outstanding and overdue invoices,
  record EFT payments, application pipeline, demand by suburb, open maintenance, tenancies needing setup
- **Billing**: approving an application opens a tenancy; setting its rent issues the deposit and
  first-month invoices; monthly rent and office invoices are issued automatically; overdue invoices
  are flagged; an optional reservation deposit can be switched on in Admin → Payment settings
- **PayFast payments**: signed checkout, verified payment notifications (signature, source, amount and
  PayFast confirmation), automatic receipts, and secure pay links for people without an account
- Private data is locked down: applications, documents, demand and submissions are admin-only;
  ID numbers and revenue are admin-read-only; workflow status can only be changed by staff

## Deploy on Railway

1. **Push this folder to GitHub** (see "Push to GitHub" below).
2. In Railway: **New Project → Deploy from GitHub repo** and pick the repository.
3. In the same project: **New → Database → PostgreSQL**.
4. Open the web service → **Variables** and add:

   | Variable | Value |
   | --- | --- |
   | `DATABASE_URL` | `${{Postgres.DATABASE_URL}}` |
   | `PAYLOAD_SECRET` | a long random string (`openssl rand -hex 32`) |
   | `ADMIN_EMAIL` | your admin login email |
   | `ADMIN_PASSWORD` | a strong password (change it in `/admin` afterwards) |
   | `UPLOADS_DIR` | `/data/uploads` |

5. Web service → **Settings → Volumes → Add volume**, mount path **`/data`**
   (keeps uploaded photos and applicant documents across redeploys).
6. Web service → **Settings → Networking → Generate Domain**.
7. Deploy. On first start the app automatically:
   - creates all database tables (migrations in `src/migrations`),
   - creates your admin account from `ADMIN_EMAIL` / `ADMIN_PASSWORD`,
   - seeds 5 suburbs and 6 verified demo homes with stand-in photos
     (turn off with `SEED_DEMO_DATA=false`).

   Railway waits for `/api/health` before switching traffic, so the site goes live only once
   the database is ready.

### Going live with PayFast

Until you add PayFast credentials, payments run against the PayFast **sandbox** (the pay page shows a
"Test mode" note and no money moves). To take real payments, add these variables in Railway:
`PAYFAST_MODE=live`, `PAYFAST_MERCHANT_ID`, `PAYFAST_MERCHANT_KEY` and `PAYFAST_PASSPHRASE`
(the passphrase must match the one set in your PayFast dashboard). PayFast notifies
`https://<your-domain>/api/payfast/notify` automatically for every payment.

### Staff workflow

1. Review applications in **Admin → Applications**; set status to **Approved**.
2. A tenancy is created. For rooms the rent comes from the home; for offices, open the tenancy and set
   the monthly rent. Link the tenant's member account if they applied without one.
3. The tenant is invoiced for deposit and first month and pays online. Their tenancy becomes active.
4. Monthly invoices follow automatically. Record EFT payments from `/ops`.
5. To give a landlord the partner portal, set their account's **Role** to *Property partner* and choose
   them as **Partner** on their homes.

Custom domain: add it under Networking, then set `SITE_URL=https://yourdomain.co.za` and redeploy.

Build and start commands are in `railway.json` (`pnpm build`, `pnpm start`); Node 24 via `.nvmrc`.

## Run locally

Requirements: Node.js 22.12+ (24 recommended), pnpm 10, PostgreSQL 14+.

```bash
cp .env.example .env        # then fill in DATABASE_URL, PAYLOAD_SECRET, ADMIN_EMAIL/PASSWORD
pnpm install
pnpm dev                    # http://localhost:3000  ·  admin at /admin
```

In development the schema syncs automatically. Production build: `pnpm build && pnpm start`.

## Changing the data model

After editing anything in `src/collections`:

```bash
pnpm generate:types                 # refresh src/payload-types.ts
pnpm migrate:create my-change       # writes a new file to src/migrations
```

Commit the migration; it runs automatically on the next deploy.

## Content notes before launch

- Demo homes use stand-in photos (downloaded from Unsplash on first boot; a generated
  illustration is used if the download fails). Replace them in **Admin → Media / Homes**.
- Prices, suburb safety/transport notes and legal wording are marked on the site as
  illustrations pending real quotes and legal review.
- Email is not configured: Payload prints admin password-reset emails to the server log.
  Add an email adapter (e.g. `@payloadcms/email-nodemailer`) when you need outgoing email.
